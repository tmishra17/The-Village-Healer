# The Village Healer

An AI health assistant for people in rural India (and the Global South broadly) who live far from a doctor. It is **NOT a replacement for doctors** — it never diagnoses. It listens to a patient's story (voice-first, in plain language), assesses **how urgent** the problem is, gives safe self-care guidance for minor issues, and for anything serious it helps the patient actually get to care — accounting for the real barriers of money, distance, and time.

Built as part of the AI Agents capstone (see `agents-capstone-projects.pdf`, "The Village Healer" chapter).

## The Problem

In many regions of rural India the physician-to-population ratio is roughly 1:100,000 (vs. 1:400 in high-income countries). Villages of 3,000–5,000 people often have no resident doctor; the nearest clinic is a 10–20 km journey that costs bus fare, lost wages, and time a farmer in harvest season cannot spare. Yet almost everyone carries a smartphone. If reliable healthcare *guidance* can live on that phone, a critical gap closes.

## The Cardinal Rule: Do Not Play Doctor

The system must **never diagnose**. This is not a limitation to apologize for — it is the boundary that makes the work legitimate. Instead of a diagnosis, it does something narrower and more honest:

- **Narrows possibilities** — given symptoms, what would a clinician want to rule out?
- **Assesses urgency** — immediate care, care within 1–3 days, or home monitoring?
- **Flags red signs** — features that demand professional evaluation.
- **Contextualizes barriers** — what actually stands between this person and care, and how to get past it.

The doctor makes the diagnosis. This system is their assistant, not their replacement. **Decision support, not diagnosis.**

## How It Works

Every health conversation ends in exactly one of three urgency levels:

| Level | Meaning | Agent behavior |
|---|---|---|
| 🔴 **RED** | Get medical help **today** | Stops questioning, names a concrete facility (via `find_nearest_facility`), gives bridging first aid, helps solve barriers |
| 🟡 **YELLOW** | See a health worker within 1–3 days | Explains why and where; escalation criteria stated plainly |
| 🟢 **GREEN** | Self-care at home is reasonable | Says exactly what to do and exactly what change would mean "get help" |

Tie-break rule: when unsure between two levels, the agent chooses the more urgent one. The agent's uncertainty raises the level; the user's confidence never lowers it.

### The Three Poverties

Barriers to care come in three forms (after Amartya Sen): **poverty of money** (fees, medicine, fares), **poverty of means** (roads, bus schedules, clinic hours), and **poverty of time** (a farmer loses ₹1,000–2,000/day during harvest). The agent acknowledges these honestly — barriers change the *plan*, never the *urgency*. For urgent cases it reframes the choice as arithmetic the user can own: a small cost today (an afternoon + bus fare + medicine) against a much larger one later (weeks of lost work if an infection spreads). Then the adult decides. The agent informs; it does not command.

### Persuasion With Respect

Modeled on the "Conversation with Rajan" design blueprint in the capstone brief: validate the user's constraints, be honest about risk (e.g., tetanus from a rusty sickle), give concrete route/cost/time information, and invite their agency ("What do you think?"). Reassure about the *process and decision*, never the *outcome* — "everything will be fine" is a banned phrase.

### Pre-Visit Summary for the Provider

On patient request (or in a RED emergency), the agent compiles what it learned into a medical-record-style pre-visit summary and sends it to the receiving facility (`send_patient_data`), so the clinician starts informed: chief complaint, history, reported findings, red flags noted, and barriers to care — clearly marked as generated by an assistant, not a licensed provider.

## Architecture

The orchestrator is a **Google ADK agent** whose tools are served over **MCP** (Model Context Protocol) by a **FastMCP** server — modular by design so future cohorts can plug in new tools (new classifiers, new red-flag rules, new domains like snake bites or maternal health) without rewriting the conversation logic.

```
Patient (voice/text on phone)
        │
        ▼
Village Healer Agent  (Google ADK + LiteLLM → self-hosted gpt-oss-20b)
  • triage protocol (RED/YELLOW/GREEN, red-flag checklist)
  • safe self-care guidance (strict allowlist, ORS-only remedy)
  • barrier reasoning (money / means / time)
        │  MCP (stdio)
        ▼
MCP_Server.py  (FastMCP)
  • search(query)                    — Serper web search (WHO guidelines, local info)
  • get_village_context(village, q)  — village location, clinic logistics
  • find_nearest_facility(village)   — nearest care facility within the patient's budget
  • send_patient_data(text, email)   — pre-visit summary emailed to the facility
```

Target village: **Bolagarh, Odisha** — the capstone requires a real village with a real bus schedule and a real clinic, not a hypothetical one.

## Getting Started

**Prerequisites:** Python ≥ 3.10, [uv](https://docs.astral.sh/uv/), a [Serper](https://serper.dev) API key, a Gmail app password (for provider summaries), and an OpenAI-compatible model endpoint (the agent currently points at a self-hosted `gpt-oss-20b` via LiteLLM — edit `MODEL` in `Village_Healer/agent.py` to use your own).

1. Install dependencies:

   ```bash
   uv sync
   ```

2. Create a `.env` in the project root:

   ```env
   SERPER_API_KEY=...
   GMAIL_ADDRESS=...
   GMAIL_APP_PASSWORD=...   # Gmail App Password, not your normal password
   ```

3. Run the agent with the ADK dev UI (the agent launches the MCP server itself over stdio):

   ```bash
   uv run adk web
   ```

## Evaluation Plan

Four dimensions, per the brief:

- **Technical** — triage confusion matrix (false *Greens* on true *Reds* matter most), SOAP extraction precision/recall, classifier top-k accuracy stratified by skin tone, < 30 s end-to-end latency.
- **Clinical** — physician review of 20–30 outputs; verify the cardinal rule holds ("signs suggest infection" ✅, "you have cellulitis" ❌).
- **Human factors** — usability for low-literacy users, voice reliability in noisy environments, natural local-language phrasing.
- **Safety & adversarial** — red-team with blurry images, contradictory narratives, and edge cases; audit for bias across skin tone, age, and gender; document failure modes and graceful fallbacks.

## Safety Boundaries

- Never names a diagnosis; never recommends or doses any medication (ORS for dehydration is the single exception).
- Never promises outcomes; never lets cost, distance, or user preference lower the urgency level.
- Never ends a RED conversation without naming a concrete place to go; critical emergencies are pointed to **112**.
- Self-harm disclosures are treated as RED for a *human* response, including the Tele-MANAS helpline **14416**.
- Every substantive reply ends with a reminder: this is guidance, not a diagnosis — see a certified medical professional.

> *"Technology that does not serve the poor, and does not respect their agency, is not innovation."*
